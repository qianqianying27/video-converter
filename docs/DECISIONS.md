# 决策记录（ADR）

记录本项目在三天内的关键技术选择、理由与取舍，便于复盘与面试讲解。

---

## ADR-001 界面选型：PySide6（Qt），不做 Web 套壳

**背景**：JD 明确接受 Qt；任务要求「界面选型与客户端关联不能为 0」。

**决策**：使用 PySide6 实现原生 Windows 桌面客户端。

**理由**：
- 原生窗口、系统文件对话框、资源管理器拖拽、任务栏进度等客户端特征直接可得；
- Electron / Tauri 会被看成网页套壳或引入 Rust 工具链风险，三天内不划算；
- WPF/C# 没有现成经验，笔试不是学习场。

**代价**：Python 打包体积较大（约 100MB+），但 onedir + 内置 ffmpeg 仍在可接受范围。

---

## ADR-002 转码实现：ffmpeg 命令行 + QProcess

**背景**：题目允许直接调 ffmpeg CLI，不要求接 API。

**决策**：所有转码都通过 `ffmpeg.exe` 子进程执行，参数用列表传递（不经过 shell）。

**理由**：
- 参数构建是纯函数，可单测、可打印、出问题能直接复制命令复现；
- 不引入 ffmpeg-python 等封装，减少版本兼容与隐式行为；
- 用 `QProcess` 而不是 `subprocess.run`：天然事件循环、可读 stdout、可 kill，不卡 UI。

**代价**：需要自己解析进度和错误输出（已封装在 `progress.py` / `converter.py`）。

---

## ADR-003 视频信息：ffprobe JSON

**决策**：`ffprobe -print_format json -show_format -show_streams`，解析逻辑与进程调用分离。

**理由**：
- JSON 稳定，字段齐全（旋转、像素格式、音轨参数都能拿到）；
- `parse_ffprobe_json` 纯函数化，单测不需要真实视频。

**注意**：旋转 90/270° 时宽高互换，否则竖屏视频会显示错误分辨率。

---

## ADR-004 缩略图：多时间点回退 + 后台线程

**决策**：按 10% → 50% → 0% 依次抽帧；QThreadPool 后台执行；失败显示占位图。

**理由**：
- 10% 位置通常比首帧更有代表性（首帧常是黑场/台标）；
- 极端文件可能 seek 失败，回退保证「有图可看」；
- 抽帧是 IO + 解码操作，必须离开 UI 线程，否则批量添加会卡。

**优化**：`-ss` 放在 `-i` 之前做快速 seek；结果按「路径 + mtime」缓存，重复添加不重复抽帧。

---

## ADR-005 进度解析容错

**决策**：优先 `out_time_us`，回退 `out_time_ms`（ffmpeg 历史原因实际是微秒），再回退 `out_time` 字符串；
没有时长或字段缺失时百分比为 `None`，UI 显示「处理中」。

**理由**：`-c copy` 等场景可能不输出时间字段；解析失败不能让进度条卡死或崩溃。

---

## ADR-006 队列串行执行

**决策**：同一时刻只跑一个 ffmpeg，队列顺序执行。

**理由**：
- 并行转码会互相抢 CPU，每个都变慢，用户感知更差；
- 串行实现简单，状态机清晰，取消语义明确。

**代价**：大批量任务总时长不变；后续可加并发度设置。

---

## ADR-007 取消 = kill + 删除半成品

**决策**：取消时 `QProcess.kill()`，并在结束回调里删除未完成的输出文件。

**理由**：半成品文件会让用户误以为转换成功；删除后重试不会产生 `_2`、`_3` 垃圾文件。

---

## ADR-008 内置 ffmpeg 优先，二进制不入库

**决策**：运行时按「用户指定 → 项目 `bin\` → 系统 PATH」顺序查找；仓库不提交 ffmpeg 二进制，提供 `scripts/fetch_ffmpeg.ps1`。

**理由**：
- ffmpeg 静态包约 170MB，超过 GitHub 单文件 100MB 限制，且拖慢 clone；
- 打包时（PyInstaller `--add-data "bin;bin"`）会把二进制一起带入产物，最终用户无感；
- 来源固定为 BtbN 的 GPL 构建，README 记录获取方式，可复现。

---

## ADR-009 输出命名规则

**决策**：`<原文件名>_<预设>.<扩展名>`，冲突时追加 `_2`、`_3`。

**理由**：一眼能看出转换来源与目标格式；不覆盖用户已有文件。

---

## ADR-010 错误信息中文化

**决策**：ffmpeg 失败时取 stderr 最后一行，包装为「转换失败：…」；ffprobe/缩略图失败给中文提示。

**理由**：目标用户不是开发者，直接抛英文 stderr 不可用；同时保留原始信息便于排查。

---

## ADR-011 会话总结与决策记录

**决策**：开发过程即维护 `docs/DECISIONS.md`，结束时生成 `SESSION_SUMMARY.md`，记录需求、决策、测试结果与反馈。

**理由**：题目第 4 条明确要求；同时这份文档本身就是「AI 工程能力」的展示——可追溯、可复盘。
